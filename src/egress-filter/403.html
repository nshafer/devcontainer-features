If you are an agent working in this container: you cannot fix this yourself, and trying to work around it will not succeed. There is deliberately no command in here that widens the allowlist. Retrying, switching to a mirror or registry, or disabling certificate verification will all fail the same way, because the block is a firewall rule and not a TLS or DNS problem.

Ask the person you are working with to allow the host. Two places, and the difference matters:

  • Their machine, ~/.config/egress-filter/allowlist.txt — applies to every container, takes effect within a couple of seconds, no restart.
  • This repo, .devcontainer/egress-allow.txt — applies to this project, and needs the container restarted before it takes effect.

A bare name allows that host; a leading dot allows the domain and its subdomains. Run egress-status to see what is currently allowed and where it came from, and cat /usr/local/share/nshafer-egress-filter/BLOCKED.md for the long version.
